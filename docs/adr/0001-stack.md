# ADR 0001: TypeScript stack

Status: accepted (2026-09-30)

## Decision

- **Language:** TypeScript on Node 22 across the API, worker, MCP servers and web app.
- **API:** NestJS 11 on the Fastify adapter. Validation with zod schemas shared from `packages/shared`, not class-validator, so the web app and API use the same contracts.
- **Database:** PostgreSQL 16 with pgvector (for the knowledge base in Phase 4) and pg_trgm. Drizzle ORM with SQL migrations generated by drizzle-kit and committed.
- **Queues and timers:** Redis + BullMQ.
- **Web:** Vite + React 19 + React Router, unstyled until the frontend phase.
- **Tests:** Vitest. Integration tests hit a real Postgres and Redis (service containers in CI, Docker Compose locally) rather than mocks.

## Notes

- We pinned to the current majors we know well (NestJS 11, TypeScript 5.9, Vitest 3, zod 3) even though newer majors exist, to avoid churn during the MVP. Upgrades get their own PRs.
- NestJS needs decorator metadata, so packages compile with `tsc`, and Vitest uses SWC (`unplugin-swc`) for the API.
- The plan mentioned Testcontainers; we use CI service containers instead, which is simpler and works in environments without a Docker daemon.
